# PoleGuard — Role-Based Access Control (RBAC) & Feature Matrix

PoleGuard delivers an enterprise-grade safety platform designed for electric distribution grids. A single unified Flutter application (`frontend-mobile/`) dynamically adapts its user interface, data permissions, and action capabilities across **5 distinct user roles**.

---

## 1. Executive Role Summary

| Role | Target Persona | Primary Mission | Access Security |
| :--- | :--- | :--- | :--- |
| **CITIZEN** | General Public & Pedestrians | Proximity danger warnings, nearby pole check, photographic hazard reporting, RAG safety assistant | Public Self-Registration (Instant Active) |
| **TECHNICIAN** | Linemen & Field Engineers | Work order receipt, fault acknowledgement, on-site diagnostics, repair photo upload, resolution certification | Staff Key Required (`POLEGUARD-SECURE-2026`) |
| **ENGINEER** | Sub-Division Technical Supervisors | Fleet predictive health, AI classification review, work order dispatch & delegation, technical oversight | Staff Key Required (`POLEGUARD-SECURE-2026`) |
| **AUTHORITY** | Municipal Disaster Management / Police | Citywide safety index, overdue incident escalations, geo-fenced public broadcast, emergency grid cutoffs | Staff Key Required (`POLEGUARD-SECURE-2026`) |
| **ADMIN** | System Administrators & Evaluators | User account management, pole asset registry, system audit logs, Judge Demo Control Center | Staff Key Required (`POLEGUARD-SECURE-2026`) |

## 3. Security & Registration Architecture

### Public Citizen Sign-Up
- Any citizen can sign up using email, password, full name, and municipal zone.
- Account is automatically activated (`is_active=True`) immediately upon registration.

### Staff Role Authorization Protection
- To protect utility power grid controls from unauthorized public tampering, selecting **Technician**, **Engineer**, **Authority**, or **Admin** during sign-up requires the departmental authorization key:
  ```text
  POLEGUARD-SECURE-2026
  ```
- If the correct key is provided, the staff account is activated immediately.
- If an invalid key or no key is provided, the account is created with `is_active=False` and placed in the Admin Review Queue.

### JWT Token Claims
Tokens generated by `POST /api/v1/auth/login` include the following claims:
```json
{
  "sub": "tech14@poleguard.internal",
  "role": "TECHNICIAN",
  "user_id": "usr-tech-01",
  "zone": "Sector 4",
  "exp": 1772712000
}
```
All mutating backend endpoints enforce strict server-side RBAC dependencies (`require_role([...])`), rejecting unauthorized requests with `403 Forbidden`.
